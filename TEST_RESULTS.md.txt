# Результаты тестирования Acquiring CRM API

## 1. Общая информация

- **Проект:** Acquiring CRM API
- **Тип:** учебный REST API-прототип.
- **Технологии:** FastAPI, PostgreSQL.
- **Инструменты тестирования:** Swagger UI, PowerShell, SQL-запросы в PostgreSQL.
- **Период тестирования:** 23–24.10.2026.
- **Окружение:** локальное.

Статусы:
- **PASS** — фактический результат соответствует ожидаемому.
- **FAIL** — фактический результат не соответствует ожидаемому.
- **BLOCKED** — тест невозможно завершить из-за ограничений окружения или зависимости.

## 8. Ограничения текущего прототипа

- Интеграция с ФНС не реализована.
- Авторизация и проверка прав доступа не реализованы.
- Связь вложения с конкретной заявкой не реализована.
- Антивирусное сканирование не реализовано.
- Проверка содержимого файла ограничена проверкой сигнатуры и расширения; полноценная проверка безопасности файлов не реализована.
- Файлы хранятся в локальной файловой системе в папке `uploads`.
- Отказоустойчивость файлового хранилища и резервное копирование не проверялись.
- Конкурентные запросы и нагрузочное тестирование отдельно не проверялись.
- Проверки не подтверждают промышленную готовность системы.

## 9. Итоговые выводы

В ходе тестирования локального учебного прототипа проверены:

- создание заявок и базовая валидация входных данных;
- идемпотентность запросов при одинаковом и изменённом теле;
- сохранение заявок и ключей идемпотентности в PostgreSQL;
- загрузка вложений, ограничения по размеру и проверка сигнатуры;
- сохранение метаданных вложений в PostgreSQL;
- получение метаданных и скачивание файлов;
- целостность скачанного файла по SHA-256;
- поведение API при ошибках БД и недоступности физического файла;
- ответы API на неподдерживаемые HTTP-методы.

**Общий вывод:** основные проверенные сценарии создания заявок и работы с вложениями завершились ожидаемыми результатами в локальном окружении. Это подтверждает работоспособность проверенных функций, но не является доказательством промышленной готовности API.

Для дальнейшего развития проекта целесообразно проверить конкурентные запросы с одинаковым `Idempotency-Key`, реализовать связь вложений с заявками и добавить авторизацию и контроль доступа.
