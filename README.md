# Acquiring CRM API

## О проекте

Учебный проект системного анализа: API для создания заявок на подключение эквайринга и ручной проверки ИНН.

**Цель:** описать взаимодействие сайта и мобильного приложения с CRM, правила создания заявок, обработку ошибок и процесс ручной проверки ИНН.

## Функциональность

- Создание заявки на подключение эквайринга.
- Валидация входных данных.
- Защита от повторного создания заявки с помощью `Idempotency-Key`.
- Загрузка подтверждающего документа.
- Ручная проверка ИНН сотрудником.
- Разделение статуса заявки, статуса проверки ИНН и статуса ручного разбора.
- Контроль доступа и аудит операций.
- Обработка ошибок API.

## API-эндпоинты

| Метод | Эндпоинт | Назначение |
|---|---|---|
| POST | `/applications` | Создание заявки |
| POST | `/attachments` | Загрузка документа |
| POST | `/applications/{applicationId}/inn-verification` | Сохранение результата ручной проверки ИНН |

## Основные бизнес-правила

### Создание заявки

Обязательные поля: `fullName`, `phone`, `inn`, `source`.

Источник заявки: `SITE` или `APP`.

Для повторных запросов используется `Idempotency-Key`:
- одинаковый ключ и одинаковые данные не создают дубликат;
- одинаковый ключ с другими данными приводит к `409 IDEMPOTENCY_KEY_REUSED`.

### Загрузка документа

- Допустимые форматы: PDF, PNG, JPEG.
- Максимальный размер: 10 МБ.
- Сервер должен проверять фактическое содержимое файла и безопасность.
- После успешной загрузки возвращается `attachmentId`.

### Ручная проверка ИНН

| Результат | Статус проверки | Ручной разбор |
|---|---|---|
| `COMPANY_FOUND` | `VERIFIED` | `NOT_REQUIRED` |
| `LIQUIDATED` | `LIQUIDATED` | `REQUIRED` |
| `NOT_FOUND` | `NOT_FOUND` | `REQUIRED` |

При `LIQUIDATED` и `NOT_FOUND` заявка направляется на ручной разбор и автоматически не закрывается.

Идентификатор сотрудника и время проверки определяет Backend. Результат проверки и обязательная запись аудита должны сохраняться атомарно.

## Обработка ошибок

| HTTP | Назначение |
|---|---|
| 400 | Ошибка валидации |
| 401 | Пользователь не авторизован |
| 403 | Недостаточно прав |
| 404 | Ресурс не найден или недоступен |
| 409 | Конфликт или недопустимое состояние |
| 413 | Превышен размер файла |
| 415 | Формат файла не поддерживается |
| 422 | Некорректное содержимое файла или ошибка проверки безопасности |
| 503 | Временная недоступность сервиса |

## Артефакты проекта

- `openapi.yaml` — контракт API в формате OpenAPI 3.0.3.
- `acquiring_api_attachment_test_cases.xlsx` — тест-кейсы загрузки документов.

## Тестирование

Подготовлены тест-кейсы для успешной загрузки файлов, ошибок валидации, превышения размера, неподдерживаемых форматов, отсутствия авторизации и прав, а также недоступности хранилища.

**Важно:** тест-кейсы описывают ожидаемое поведение. Реальный Backend и фактическое выполнение тестов пока не заявлены.
